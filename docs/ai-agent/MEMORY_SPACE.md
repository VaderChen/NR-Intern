# 回憶空間（實驗性）

跨對話的共同記憶：在某個對話裡確認過的偏好、決策與作法，下一個對話不必重講。

管理介面「實驗性功能」有開關（設定欄位 `memory_space`，預設關閉）。**機制尚未實作**，
目前只保存開關狀態。這份文件是實作前要先定下來的設計。

以下准入、共享範圍、召回時機與淘汰數值均為**提案**，不是已上線的保護機制。開關可由
`GET／PUT /api/v1/admin/service-settings` 讀寫；省略時保留，切換不會改變既有 `memory.enabled`、
`memory.auto_recall`、`memory.allow_writes` 或 scope 的行為。

## 為什麼不是直接打開現有的長期記憶

`src/memory` 已經是跨 session 的：`ScopeForSession` 預設用 Agent 當 scope，
`memory_remember`／`memory_search`／`memory_forget` 也都在。缺的不是儲存，是**節制**：

| 現況 | 問題 |
| --- | --- |
| 寫入完全由模型決定 | 沒有准入條件，什麼都能寫進去，只會越積越多 |
| 每個 Run 自動召回一次 | 沒有相關度門檻，不相關時照樣佔提示 |
| 單次注入上限 8 條／8,000 字 | 8,000 字每輪重送，對本機模型是實質負擔 |
| 沒有淘汰機制 | 記憶只增不減，時間夠久必然劣化成雜訊 |
| scope 預設是整個 Agent | 甲專案的內容會出現在乙專案的對話裡 |

回憶空間是在同一套資料模型上補這五件事，不是另建一套儲存。

## 1. 什麼可以進入（准入過濾）

三個條件全部成立才寫入：

1. **型別**：只收 `preference`、`decision`、`constraint`、`procedure`。
   `fact` 預設不收——「這個檔案有 300 行」會過期，而且下次查得到。
2. **可重用**：換一個對話、換一天仍然成立。只對這次任務成立的路徑、錯誤訊息、
   暫時狀態一律不收。
3. **不可推導**：倉庫裡查得到的（程式結構、git 記錄、專案說明檔）不收。
   查一次比記一輩子便宜，而且不會過時。

硬性排除：密碼、金鑰、權杖、個人資料。這一條不看模型判斷，由寫入端以樣式檢查擋下。

### 去重與取代

寫入前先用同一組關鍵字檢索既有記憶：

- **語意重複** → 更新原本那筆的 `last_accessed_at` 與 `confidence`，不新增。
- **內容矛盾** → 以 `supersedes` 建立取代鏈，舊的轉 `superseded`，不刪除。

兩者現有資料模型都已支援（`Supersedes`／`SupersededBy`／`MemoryStatusSuperseded`），
不需要新欄位。

## 2. 共享範圍

寫入時決定，三層：

| Scope | 意義 | 用途 |
| --- | --- | --- |
| `session:<id>` | 只有這個對話 | 預設，不進入回憶空間 |
| `project:<id>` | 同一個專案的所有對話 | 回憶空間的主力 |
| `workspace:<id>` | 跨專案 | 使用者本人的偏好、通則 |

回憶空間打開後，預設 scope 從「整個 Agent」收斂成**專案**；要跨專案必須明確升級。
`ScopeForSession` 已支援用 session metadata 的 `memory_scope` 指定，沿用即可。

## 3. 調用時機

不是每一輪都注入。三個觸發點：

1. **Run 開始**：用這次的使用者輸入檢索一次（與工具檢索共用查詢字串，見
   `harness.retrievalQuery`——跟進提問只剩代名詞時也檢索得到）。
2. **同一個工具連續失敗兩次**：用失敗訊息再檢索一次。「這個錯以前遇過」正是
   記憶最有價值的時刻，也是目前完全沒有利用的時刻。
3. **模型主動呼叫 `memory_search`**：不受上述限制。

其餘回合不注入，避免同一批內容每輪重送。

## 4. 窗口大小

- 單次注入上限 **6 條／1,200 字**（現況是 8 條／8,000 字）。
- 排序分數：`相關度 × 0.6 + 新鮮度 × 0.2 + 命中率 × 0.2`。
- **低於相關度門檻就完全不注入**：寧可空手，不要塞雜訊。這一條比上限重要——
  沒有它，窗口再小也只是把雜訊裁短。

## 5. 成長上限

每個 scope 上限 **500 條**。到達上限時依價值分數淘汰：

- 90 天未被召回、且從未被引用 → 優先淘汰。
- `superseded` 狀態保留 30 天供稽核後移除。
- 使用者明確 `memory_forget` → 立即移除。

淘汰是轉成 `forgotten` 狀態，不是刪資料——與 transcript 撤回同一個原則：
出問題時要能查回「當時到底記了什麼」。

## 6. 為什麼預設關閉

跨對話記憶會讓「這次對話的行為」取決於使用者看不見的狀態，出錯時很難重現。因此：

- 預設關閉，可隨時關掉，關掉後不影響既有記憶資料。
- 召回內容一律包在 `<recalled_memories>` 裡標成外部資料，不得凌駕當下指令或
  實際工具結果（現有實作已經這樣做，回憶空間沿用）。
- 召回哪幾條要能在處理過程裡看到，讓使用者知道這次答案受了什麼影響。

## 實作順序

1. 准入過濾與去重（第 1 節）——沒有這層，其他都是在整理垃圾。
2. scope 收斂到專案（第 2 節）。
3. 調用時機與窗口（第 3、4 節）。
4. 淘汰（第 5 節）——資料量真的長起來之後才需要。
