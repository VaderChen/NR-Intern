# 2026-09-21 深度檢查與修正紀錄

## 邊界

本輪保持畫面、按鈕、使用者操作、HTTP 路由、SSE 格式、登入／OAuth／帳號匯入方式與權限規則不變。
不讀取真實帳號或金鑰，不操作正在執行的 APP，不執行 Git、封裝、發布。
修改前保存本次 `.bak`；驗證通過後只移除本次備份，保留所有先前修改。

## 檢查方式與覆蓋

全專案執行 Go 靜態分析與指定建置，深度追蹤 Application Run／核准／取消／LOOP、
HTTP SSE、事件儲存與位移索引、明細保留、工具 Runtime 與 Harness 收尾的呼叫鏈。
交叉核對 Provider 重試、拒絕、MCP 工具契約、SSH／HTTP 取消與既有前端重連實作，
使用相關合成 Smoke／race 測試驗證。這不是逐行證明所有程式均正確，也不是所有平台的實機驗收。

## 已修正的具體問題

| 問題 | 原因 | 修正與驗證 |
| --- | --- | --- |
| Run 已完成但 SSE 漏掉尾筆 | 先讀事件、再讀狀態，兩次讀取之間可發生終態轉換 | 終態提交與事件批次讀取共用鎖；阻塞終止寫入的合成測試驗證等待者不提前返回 |
| 終止事件寫入失敗後等待卡住 | 部分路徑只有成功追加事件才通知訂閱者 | 狀態落盤後即使事件失敗仍通知；重連依 durable Run 補齊事件 |
| 同步失敗可能導致重複終態 | 回報寫入失敗不代表磁碟完全沒有該筆資料 | 修復前重新讀尾筆；覆蓋未寫入與已寫入後回報錯誤兩種情境，不重跑引擎 |
| 保留數無法正確收斂 | 只檢查固定最舊區間，遇到 active／protected 後未補查其他候選 | 維持原 500 筆基準，持續掃描可淘汰候選；保護進行中工作，保留用量快照 |
| 派送前拒絕被誤當工具執行失敗 | Registry 的通用失敗回覆缺少執行狀態 | 明確標記 `not_dispatched`，派送入口與驗證完成後檢查取消；權限判斷不變 |
| Run panic 值可能洩漏敏感資料 | panic 原文進入日誌及 RunError | 保留 Run ID、panic 型別與堆疊，不回傳或記錄原文；以合成標記驗證未外洩 |
| 取消／失敗可能帶著舊完成結果 | 從完成候選切換終態時仍保留 Result | 清除非完成終態的候選結果；既有成功終態仍不被晚到失敗覆寫 |

終態修復只有在確認缺少終止事件時才取得准入鎖，並重新讀取 Run；正常增量重播仍使用
Run 分片鎖及位移索引，沒有將不同任務的正常事件讀取改成全域序列。
狀態與既有終止事件矛盾、或事件中段損壞時回報錯誤，不偽造完成，也不覆寫原紀錄。

## 驗證

- `go build -buildvcs=false ./src/...` 與 `go vet ./src/...`。
- Application、HTTP API、filestore、工具 Runtime 的相關 Smoke／race 測試。
- Harness、OpenAI-compatible adapter、SSH、HTTP fetch、核准與問答的相關 Smoke／重試／取消／契約測試，啟用 race。
- JavaScript 語法檢查；既有重連、Responses 表單與多帳號選檔／DLG 的合成 Smoke。
- Windows amd64、CGO 關閉的本輪後端套件交叉編譯。

本機建置仍有既有的 duplicate `-lobjc` 警告。沒有實際呼叫上游、進行真實帳號登入、
注入 APP 斷線或在 Windows 上執行安裝與運行測試。

## 保留限制與後續驗收

- 取消回覆代表 Run 已接受取消，不保證所有外部系統已停止；派送後未知結果仍須先查證，不能宣稱恰好執行一次。
- 磁碟永久故障、損壞紀錄、跨程序共同寫入或惡意檔案替換，不在本輪修復的可靠性保證內。
- 已清理的舊事件本文不會復原；若仍有 Run 明細，僅能補回終態。
- 排程不同時間點的工作仍可能重疊；本輪未變更排程操作或執行政策。
- 實機的長時間執行、Proxy 斷線／過載、舊 APP 換版與 Windows 安裝仍需獨立驗收，不能以合成測試代替。
